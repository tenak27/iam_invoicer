À qui s'adresse ce guide ?

Au technicien ou à l'administrateur qui installe IAM INVOICER chez un client ou dans sa propre entreprise. Les chapitres 1 à 10 couvrent l'installation, le chapitre 11 le paramétrage de chaque module, les chapitres 12 à 18 l'exploitation au quotidien.

Conventions

Les commandes à taper sont dans des blocs sombres. Les chemins de menu sont en gras, par exemple Société & paramètres → Messagerie. Les encadrés orange signalent une contrainte, les rouges un risque de perte de données ou de sécurité.

1 Avant de commencer : choisir l'architecture

IAM INVOICER range ses données à un seul endroit, que l'on choisit sur l'écran de connexion de l'application de bureau (lien Base de données … — modifier). Trois modes existent :

Ce poste uniquement

Base intégrée dans l'ordinateur.

Pour : une petite structure avec un seul ordinateur.

Synchronisation : aucune.

Serveur en ligne (domaine)

Serveur sur Internet, ex. facturation.iam.bf.

Pour : plusieurs sites, téléphones, tablettes, accès à distance.

Synchronisation : temps réel.

Serveur du bureau

Base PostgreSQL sur une machine du réseau local.

Pour : plusieurs ordinateurs dans les mêmes locaux, sans Internet fiable.

Synchronisation : réseau local.

Choisir dès le départ

Le transfert automatique d'une base « Ce poste » vers un serveur n'existe pas encore. Passer d'un mode à l'autre oblige à ressaisir les fiches ou à demander une reprise de données. Si l'entreprise prévoit d'avoir un jour plusieurs postes ou des téléphones, commencez directement avec le serveur en ligne.

Recommandation

  • Commerce ou prestataire avec un seul ordinateur : « Ce poste uniquement », avec une sauvegarde hebdomadaire sur clé USB.
  • Entreprise avec plusieurs postes, agences ou commerciaux sur le terrain : serveur en ligne sur le domaine de l'entreprise.
  • Site isolé avec une connexion Internet instable : serveur du bureau, ou serveur en ligne avec le mode hors ligne sur les postes web et mobiles.

3 Serveur en ligne sur votre domaine

Le serveur fournit à la fois l'API utilisée par toutes les applications et la version navigateur. L'installation recommandée utilise Docker : trois conteneurs, db (PostgreSQL 17), app (IAM INVOICER, port 8080 interne) et caddy (HTTPS automatique, ports 80 et 443).

3.1 Nom de domaine

  1. Chez votre registraire ou votre hébergeur DNS, créez un enregistrement A : facturation.iam.bf → adresse IPv4 du serveur. Ajoutez un enregistrement AAAA seulement si le serveur a une adresse IPv6 fonctionnelle.
  2. Attendez la propagation (de quelques minutes à quelques heures). Vérifiez avec nslookup facturation.iam.bf.
Contrainte HTTPS

Caddy ne peut obtenir le certificat que si le domaine pointe déjà vers le serveur et que le port 80 est ouvert. Si le certificat échoue, corrigez le DNS ou le pare-feu, puis redémarrez Caddy.

3.2 Préparer le serveur (Ubuntu ou Debian)

# Docker et Compose (script officiel)
curl -fsSL https://get.docker.com | sudo sh
sudo usermod -aG docker $USER      # puis se déconnecter / reconnecter

# Pare-feu : SSH, HTTP et HTTPS uniquement
sudo ufw allow OpenSSH
sudo ufw allow 80/tcp
sudo ufw allow 443/tcp
sudo ufw enable
Ne jamais exposer la base

N'ouvrez pas le port 5432 (PostgreSQL) ni le port 8080 sur Internet. Seul Caddy, en HTTPS, doit être joignable.

3.3 Installer IAM INVOICER

git clone https://github.com/tenak27/iam_invoicer.git iam-invoicer
cd iam-invoicer
cp deploy/.env.example deploy/.env
nano deploy/.env

Renseignez les deux variables du fichier deploy/.env :

VariableContenu
DOMAINLe nom de domaine, sans https:// : facturation.iam.bf
DB_PASSWORDMot de passe long et aléatoire. Générez-le avec openssl rand -hex 24. Il ne doit pas contenir @ : / #, car il entre dans l'adresse de connexion à la base.
 
docker compose -f deploy/docker-compose.yml --env-file deploy/.env up -d --build
docker compose -f deploy/docker-compose.yml ps          # les 3 services doivent être « running »
docker compose -f deploy/docker-compose.yml logs -f app # « IAM INVOICER 0.5.1 — http://0.0.0.0:8080 — base PostgreSQL db »

La première construction prend quelques minutes. Le domaine présente alors :

Proposer les installateurs au téléchargement

Chaque étiquette de version publie une Release GitHub contenant l'installateur Windows (.exe), les fichiers macOS (-arm64.dmg pour les puces Apple, -x64.dmg pour Intel), l'APK Android et l'IPA iPhone. Une commande les copie dans le dossier du site :

node tools/site/fetch-release.mjs deploy/telechargements --clean

Le site affiche alors, pour chaque plateforme, un bouton par fichier avec sa taille, met en avant l'appareil du visiteur, propose un code QR pour télécharger l'APK depuis un téléphone et publie l'empreinte SHA-256 de chaque fichier. Des fichiers déposés à la main dans deploy/telechargements/ sont pris en compte de la même façon.

Coordonnées du site

Renseignez téléphone, WhatsApp, e-mail et adresse dans site/config.js avant la construction (ou directement dans out/site/config.js sur un serveur sans Docker).

Configuration initiale à faire immédiatement

Tant que le compte administrateur n'est pas créé, la première personne qui ouvre l'adresse peut le créer. Faites la configuration initiale juste après la mise en ligne.

Contraintes
  • La connexion à PostgreSQL se fait sans chiffrement TLS : la base doit être sur la même machine ou sur un réseau privé. Les bases hébergées qui exigent TLS (certains services PostgreSQL managés) ne sont pas prises en charge pour l'instant.
  • Une seule instance du serveur par base. La répartition de charge sur plusieurs instances n'a pas été testée.
  • L'image Docker contrôle la santé du service par /health. Utilisez la même adresse pour une supervision externe.

4 Serveur du bureau (réseau local)

Les applications de bureau se connectent directement à une base PostgreSQL du réseau local. Il n'y a pas de serveur IAM INVOICER à installer, seulement PostgreSQL.

4.1 Installer PostgreSQL sur la machine serveur

  1. Installez PostgreSQL (version 17 conseillée) : installateur officiel sous Windows, apt install postgresql sous Debian ou Ubuntu.
  2. Donnez à la machine une adresse IP fixe (réservation DHCP sur le routeur), par exemple 192.168.1.10.
  3. Créez l'utilisateur et la base : 
    sudo -u postgres psql
CREATE USER iam WITH PASSWORD 'mot-de-passe-long';
CREATE DATABASE iam_invoicer OWNER iam;
\q
  4. Dans postgresql.conf, autorisez l'écoute réseau : listen_addresses = '*'.
  5. Dans pg_hba.conf, limitez l'accès au réseau du bureau : 
    host  iam_invoicer  iam  192.168.1.0/24  scram-sha-256
  6. Redémarrez PostgreSQL et ouvrez le port 5432 dans le pare-feu, pour le réseau local seulement.

4.2 Brancher chaque poste

Sur l'écran de connexion de l'application de bureau : Base de données … — modifier → Serveur du bureau, puis indiquez l'hôte (192.168.1.10), le port (5432), la base, l'utilisateur et le mot de passe. Les tables sont créées automatiquement à la première connexion.

Contraintes de sécurité
  • Le trafic vers PostgreSQL n'est pas chiffré : réservez ce mode à un réseau local de confiance (pas de Wi-Fi invité).
  • Ne redirigez jamais le port 5432 du routeur vers Internet. Pour un accès à distance, passez au serveur en ligne.
  • Les mobiles et la version navigateur ne peuvent pas utiliser ce mode.
  • La sauvegarde et la restauration se font sur la machine PostgreSQL (chapitre 13), pas depuis l'application.

5 Windows

5.1 Obtenir l'installateur

  • Installateur IAM-INVOICER-Setup-0.5.1.exe : produit par GitHub Actions (onglet Actions → build → Artifacts, archive « IAM-INVOICER-Windows »).
  • Version portable IAM-INVOICER-Setup-0.5.1.zip : à décompresser dans un dossier, par exemple C:\IAM INVOICER, puis lancer IAM INVOICER.exe. Elle sert quand l'installateur est bloqué (voir plus bas).

5.2 Installer

  1. Double-cliquez sur l'installateur. Choisissez « pour moi » ou « pour tous les utilisateurs » (ce dernier choix demande les droits administrateur), puis le dossier d'installation.
  2. Un raccourci IAM INVOICER est créé sur le bureau et dans le menu Démarrer.
  3. Au premier lancement, choisissez le mode de données (chapitre 1), puis faites la configuration initiale ou connectez-vous.

5.3 Avertissements de sécurité de Windows

Signature de code

Un certificat de signature de code (OV ou EV) au nom d'IAM Technology supprime ces trois blocages. C'est le prérequis d'un déploiement à grande échelle chez des clients.

5.4 Où sont les données ?

  • Mode « Ce poste » : %APPDATA%\IAM INVOICER\data. Un ancien dossier « IAM ERP » est repris automatiquement.
  • La désinstallation ne supprime pas ce dossier. Pour repartir de zéro, supprimez-le après avoir fait une sauvegarde.
  • Plusieurs comptes Windows sur la même machine ont chacun leur propre base en mode « Ce poste ».

7 Android

L'application Android affiche l'interface d'IAM INVOICER et se connecte toujours à un serveur en ligne (chapitre 3). Identifiant : com.iamtechnology.invoicer.

7.1 Installation directe (APK)

  1. Récupérez l'APK dans GitHub Actions (archive « IAM-INVOICER-Android »), puis copiez-le sur le téléphone (câble, e-mail, WhatsApp, Drive).
  2. Ouvrez le fichier. Android demande d'autoriser l'installation depuis cette source (Paramètres → Applications → Accès spécial → Installer des applis inconnues) : autorisez l'application utilisée pour ouvrir le fichier.
  3. Au premier lancement, saisissez l'adresse du serveur : facturation.iam.bf.
  4. Connectez-vous avec votre compte.
Contraintes de l'APK fourni par GitHub
  • C'est une version de test (« debug ») : elle est signée avec une clé de développement différente à chaque machine de compilation. Pour installer une nouvelle version, il peut être nécessaire de désinstaller l'ancienne. Les données restent sur le serveur, mais les ventes hors ligne non envoyées sont perdues.
  • Play Protect peut afficher un avertissement : choisissez Installer quand même.
  • Certains téléphones d'entreprise (gestion MDM) interdisent les sources inconnues.

7.2 Publication sur le Play Store

  1. Ouvrez un compte développeur Google Play (25 $, paiement unique).
  2. Créez une clé de signature et conservez-la en lieu sûr : la perdre empêche toute mise à jour de l'application. 
    keytool -genkey -v -keystore iam-invoicer.jks -keyalg RSA -keysize 2048 -validity 10000 -alias iam
  3. npm run android ouvre Android Studio (JDK 21 requis). Choisissez Build → Generate Signed Bundle / APK → Android App Bundle.
  4. Envoyez le fichier .aab dans la Play Console. Il faut aussi une fiche (captures, description), une politique de confidentialité et le questionnaire sur la sécurité des données.
HTTP ou HTTPS ?

Android accepte une adresse en http:// (par exemple un serveur de test sur le réseau local). En production, utilisez toujours https:// : les mots de passe et les jetons circulent sur le réseau.

8 iOS (iPhone, iPad)

Prérequis incontournables
  • Un compte Apple Developer (99 $ par an) et un Mac avec Xcode. Il n'existe pas d'équivalent de l'APK : un iPhone n'installe que des applications de l'App Store, de TestFlight ou d'un appareil enregistré par un développeur.
  • Un serveur en HTTPS avec un certificat valide. iOS refuse les adresses http://.
  • iOS 15 ou plus récent.

8.1 Publier sur TestFlight ou l'App Store

  1. Sur le Mac : npm ci puis npm run ios, qui ouvre Xcode avec ios/App/App.xcodeproj.
  2. Cible App → Signing & Capabilities : choisissez votre équipe (Team). L'identifiant est com.iamtechnology.invoicer. Il doit être libre ou enregistré dans votre compte.
  3. Choisissez la destination Any iOS Device, puis Product → Archive.
  4. Dans l'Organizer : Distribute App → App Store Connect.
  5. Dans App Store Connect, ajoutez des testeurs TestFlight (jusqu'à 10 000 par invitation e-mail), ou soumettez l'application à la validation d'Apple pour l'App Store.

8.2 Sur l'iPhone

  1. Installez TestFlight depuis l'App Store, puis ouvrez l'invitation reçue par e-mail. Vous pouvez aussi installer directement depuis l'App Store une fois l'application publiée.
  2. Au premier lancement, saisissez l'adresse du serveur, puis connectez-vous.

8.3 Fichier IPA proposé sur le site

  • IPA signé (…-ios.ipa) : fabriqué par GitHub Actions quand les secrets IOS_CERT_P12_BASE64, IOS_CERT_PASSWORD, IOS_PROFILE_BASE64, IOS_TEAM_ID (et IOS_EXPORT_METHOD : release-testing ou enterprise) sont renseignés. Sur un iPhone dont l'identifiant est inscrit dans le profil ad hoc, le bouton Installer du site (Safari, HTTPS) installe directement l'application.
  • IPA non signé (…-ios-unsigned.ipa) : fabriqué sans compte Apple. Il s'installe depuis un ordinateur avec Sideloadly ou AltStore et l'identifiant Apple de l'utilisateur ; avec un compte gratuit, l'application doit être réinstallée tous les 7 jours. À réserver aux essais.
  • Pour une diffusion à des clients, préférez TestFlight ou l'App Store : renseignez le lien dans iosUrl de site/config.js, le site affiche alors le bouton TestFlight et son code QR.
Bon à savoir

Les versions TestFlight expirent après 90 jours : publiez une nouvelle version avant cette échéance. La validation d'Apple peut demander un compte de démonstration : préparez un compte de test sur le serveur.

9 Navigateur web

Aucune installation n'est nécessaire : ouvrez https://facturation.iam.bf/app/ (ou le lien Se connecter du site) dans Chrome, Edge, Firefox ou Safari. L'interface s'adapte à chaque écran : barre d'onglets et listes en cartes sur téléphone, menu réduit aux icônes sur tablette et petit portable, contenu centré sur grand écran, boutons de 44 px sur les écrans tactiles.

  • Fonctions réservées à l'application de bureau : sauvegarde et restauration locales, choix du mode de données, impression directe sans passer par la fenêtre d'impression.

10 Premier démarrage

Au premier lancement sur une base vide (poste, serveur du bureau ou serveur en ligne), l'assistant de configuration initiale demande :

  1. La société : logo, raison sociale, pays, adresse, téléphone, puis les mentions fiscales. Le pays règle automatiquement l'identifiant fiscal (IFU au Burkina Faso et au Bénin, NCC en Côte d'Ivoire, NINEA au Sénégal, NIU au Cameroun et au Congo, NIF ailleurs), les régimes proposés, la devise et la TVA par défaut. Pour un pays autre que le Burkina Faso, faites confirmer ces valeurs par un comptable.

11 Configuration des modules

Chaque module est actif dès l'installation. Le tableau ci-dessous indique, pour chacun, ce qu'il faut paramétrer avant l'usage réel et les contraintes à connaître.

Ventes (devis, livraisons, factures, avoirs)

  • Un document est d'abord un brouillon, sans numéro. À la validation, il reçoit un numéro définitif et continu par type et par année (FAC-2026-0001), le stock est mis à jour et l'écriture comptable est passée.
  • Une facture validée ne s'annule pas : on établit un avoir.
  • Une vente au client comptoir doit être réglée en totalité. Pour une vente à crédit, il faut choisir le client.

Caisse (point de vente)

  • Chaque caissier ouvre sa caisse avec un fonds de caisse, encaisse (espèces, Orange Money, Moov Money, Wave, ou paiement mixte), puis clôture en comptant les espèces.
  • Une caisse ne peut être clôturée avec un écart que si l'écart est expliqué. Les règlements d'une caisse clôturée ne peuvent plus être supprimés.
  • Matériel : imprimante 80 mm et lecteur de codes-barres (chapitre 2). Saisissez les codes-barres dans les fiches articles.

Achats

Circuit bon de commande → réception (entrée en stock) → facture fournisseur. Créez d'abord les fournisseurs et les articles avec leur prix d'achat.

Stock multi-dépôts, lots et numéros de série

  • Créez les dépôts dans Catalogue & stock → Dépôts, transferts, lots. Le « Dépôt principal » (code PRINCIPAL) existe déjà.
  • Dans la fiche article, choisissez le suivi (aucun, par lot ou par numéro de série) avant les premiers mouvements.
  • Les quantités initiales se saisissent par un inventaire par dépôt. La valorisation se fait au coût moyen pondéré (CMUP).

Comptabilité SYSCOHADA

  • Le plan comptable SYSCOHADA révisé est fourni et modifiable. Les écritures des ventes, achats, règlements, caisse, paie et immobilisations sont générées automatiquement.
  • Les comptes de trésorerie sont fixés : 571 caisse, 552 monnaie électronique (mobile money), 521 banque.
  • Pour une reprise en cours d'année, les pièces validées avant l'activation de la comptabilité se comptabilisent avec Journaux & écritures → Générer les écritures.
  • Faites saisir les à-nouveaux (soldes d'ouverture) en opérations diverses par le comptable.

RH et paie

À faire valider avant la première paie

Les taux CNSS, le plafond, le barème IUTS, les abattements et les réductions pour charges de famille sont des valeurs par défaut. Faites-les vérifier par votre comptable, ou auprès de la DGI et de la CNSS, puis ajustez-les dans RH → Paramètres de paie. La réglementation évolue : vérifiez-les chaque année.

  • Saisissez les salariés : matricule, catégorie, salaire de base, indemnités, charges de famille, date d'embauche.
  • Part patronale CNSS détaillée (prestations familiales, risques professionnels selon l'activité, pension), taxe patronale d'apprentissage et autres cotisations (assurance maladie, mutuelle, retraite) se règlent dans RH → Paramètres de paie.
  • Paie mensuelle : préparer, ajuster les variables (primes, absences, avances), valider. Les bulletins sont produits en PDF, avec la déclaration CNSS/IUTS et l'écriture de paie.
  • Les soldes de congés se reprennent à la création du salarié.

CRM et projets

  • CRM : le pipeline (Nouveau → Qualifié → Proposition → Négociation → Gagné ou Perdu) se gère par glisser-déposer. Un prospect gagné se convertit en client et en devis.
  • Projets : renseignez le taux horaire (facturation), le coût horaire interne et le budget, global et par poste. Tâches et jalons, temps passés, dépenses avec justificatif (comptabilisées automatiquement) et refacturation avec marge permettent de suivre la marge réelle.
  • Factures récurrentes (contrats de maintenance, abonnements, loyers) : Ventes → Factures récurrentes. Les factures dues sont créées automatiquement à la connexion d'un commercial ou d'un administrateur.

Immobilisations

  • Pour chaque bien : compte d'immobilisation, date d'acquisition, valeur HT, durée. L'amortissement est linéaire, au prorata temporis.
  • Option Comptabiliser l'acquisition : contre le compte 481 (fournisseur d'investissement) ou un compte de trésorerie. Laissez-la vide si la facture d'achat est déjà comptabilisée par ailleurs, pour éviter un doublon.
  • Les dotations annuelles se passent en fin d'exercice (681 / 28xx).

Budgets et trésorerie

Saisissez un budget mensuel par compte (prévu et réalisé). La trésorerie prévisionnelle (8, 13 ou 26 semaines) s'appuie sur les factures à encaisser et à payer, la paie et les prévisions saisies, avec une alerte de découvert.

Facture certifiée (SECeF, DGI)

ModeUsage et contraintes
DésactivéAucune certification.
SimulationTeste le circuit : un code, des compteurs et un QR code fictifs sont imprimés. Sans valeur légale.
APICertification réelle à la validation. Il faut l'adresse et le jeton remis par la DGI. Communications : e-mails et SMS

  • E-mail (Société & paramètres → Messagerie). Avec Gmail : serveur smtp.gmail.com, port 587. Il faut activer la validation en deux étapes du compte Google, puis créer un mot de passe d'application : le mot de passe habituel est refusé. Le bouton « Envoyer un e-mail d'essai » vérifie le réglage.
  • SMS (Société & paramètres → SMS) : Orange (compte sur developer.orange.com, API « SMS Burkina Faso »), Twilio, ou toute passerelle HTTP du type https://…/send?to={to}&text={message}&key={key}. Les SMS sont facturés par le fournisseur.
  • Les mots de passe et clés sont stockés à part et ne sont jamais réaffichés : pour les changer, ressaisissez-les.
  • Les e-mails partent de la machine qui exécute le logiciel : du serveur en ligne, ou du poste en mode « Ce poste ». Le port 587 sortant doit y être ouvert.

Taxes de facturation

  • La TVA se règle ligne par ligne (taux du pays, 0 % pour une exonération).
  • Société & paramètres → Taxes → Ajouter les modèles du pays : droit de timbre, taxe spécifique, retenue à la source sur prestations, retenue de TVA. Les modèles sont inactifs : vérifiez les taux avec votre comptable, puis activez-les.
  • Une taxe ajoutée (ex. timbre) s'ajoute au total TTC ; elle peut être automatique sur chaque nouveau document.
  • Une retenue à la source se coche sur la facture du client concerné : elle est déduite du « Net à payer » et, à la validation, enregistrée comme règlement (449/411 sur une vente, 401/447 sur un achat).
  • Les comptes utilisés doivent exister dans le plan comptable.

Import des données existantes

  • Administration → Importer des données : clients, fournisseurs, articles, stock initial, salariés, plan comptable.
  • Fichier Excel (.xlsx), CSV, ou cellules copiées depuis Excel. Téléchargez le modèle pour partir des bonnes colonnes ; les intitulés usuels sont reconnus et la correspondance reste modifiable.
  • Ordre conseillé : plan comptable, clients et fournisseurs, articles, puis stock initial, et enfin salariés.
  • Une ligne en erreur n'empêche pas les autres : le compte rendu indique chaque ligne refusée et son motif. Une fiche existante (même code ou même référence) est mise à jour, pas dupliquée.
  • Les articles suivis par lot ou numéro de série se reprennent dans Dépôts, transferts, lots, pas par l'import du stock.

États financiers et déclarations

  • Comptabilité → Bilan : actif et passif à une date, en présentation simplifiée SYSCOHADA, avec contrôle d'équilibre ; impression et export Excel.
  • Comptabilité → Déclarations : TVA du mois (collectée par taux, déductible, TVA retenue par les clients, montant à payer ou crédit), retenues à la source à reverser et subies, salaires (cotisations et impôt).
  • Ce sont des états préparatoires : reportez les montants sur les formulaires officiels (télédéclaration, sécurité sociale) après vérification par votre comptable. Passez d'abord les écritures d'inventaire (amortissements, provisions, stocks).

Signatures électroniques

  • Le cachet et la signature de la société se chargent dans Documents & signature.
  • Signature du client sur place (doigt, stylet, souris) : fonctionne dans tous les modes.
  • Signature à distance par lien sécurisé : le client ouvre https://votre-domaine/sign/…. Il faut donc le serveur en ligne. En mode « Ce poste », renseignez une adresse publique dans Documents & signature.
  • Preuve conservée : empreinte SHA-256 du document, date, adresse IP et appareil. Si le document est modifié après la signature, l'application l'indique.

12 Mode hors ligne

Sur l'application de bureau reliée au serveur en ligne, la version navigateur et les applications Android et iOS, une coupure de réseau n'arrête pas le travail :

  • les dernières données consultées restent lisibles ;
  • les ventes, règlements, temps passés et demandes de congés saisis hors connexion sont mis en file d'attente ;
  • au retour du réseau, ils sont envoyés automatiquement, une seule fois et sans doublon. Un bandeau indique le nombre d'opérations en attente et propose un bouton d'envoi.
Contraintes
  • Une vente faite hors ligne reçoit son numéro et sa date définitifs à la synchronisation, pas au moment de la vente.
  • Les opérations en attente sont stockées dans le navigateur ou l'application de cet appareil. Elles sont perdues si l'on efface les données du navigateur, si l'on désinstalle l'application ou si l'on utilise la navigation privée avant la synchronisation.
  • Une facture certifiée SECeF (mode API) ne peut pas être validée hors ligne.
  • Ordinateur : une base locale garde les données de travail (articles, clients, documents récents, caisse). On peut démarrer et se connecter sans réseau si l'utilisateur s'est déjà connecté en ligne sur ce poste au cours des 30 derniers jours (mot de passe vérifié sur le poste, jeton chiffré par le système). L'état se suit dans Société & paramètres → Données → Base locale de ce poste.
  • Sur ordinateur, la base locale est un fichier non chiffré dans le profil de l'utilisateur Windows ou macOS : protégez la session par un mot de passe.
  • Les stocks affichés hors ligne datent de la dernière synchronisation : deux appareils peuvent vendre le même dernier article.

13 Sauvegardes et restauration

Règle 3-2-1

Gardez 3 copies des données, sur 2 supports différents, dont 1 hors des locaux (ou hors du serveur). Une sauvegarde qui n'a jamais été restaurée n'est pas une sauvegarde : faites un essai de restauration chaque trimestre.

Mode « Ce poste »

Sauvegardes automatiques (Société & paramètres → Données) : une sauvegarde complète chaque jour et au démarrage si la dernière date de plus de 24 h, dans Documents\IAM INVOICER\Sauvegardes par défaut, avec 14 copies conservées. Choisissez de préférence un dossier Google Drive, OneDrive ou Dropbox : la copie part alors hors de l'ordinateur. Seules des copies y sont déposées ; la base de travail reste sur le poste (une base ouverte dans un dossier synchronisé risquerait d'être corrompue).

À tout moment, Créer une sauvegarde produit un fichier iam-invoicer-sauvegarde-AAAAMMJJHHMM.tar.gz. La restauration se fait au même endroit (Restaurer une sauvegarde…) : l'archive est vérifiée avant de remplacer les données. Ces fonctions sont réservées à l'administrateur.

Serveur en ligne (Docker)

# Sauvegarde quotidienne à 2 h, conservation 30 jours dans deploy/backups/
chmod +x deploy/backup.sh
crontab -e
0 2 * * * /home/ubuntu/iam-invoicer/deploy/backup.sh >> /var/log/iam-backup.log 2>&1

# Copie hors du serveur (exemple avec rsync vers une autre machine)
rsync -a deploy/backups/ sauvegarde@autre-serveur:/sauvegardes/iam-invoicer/

Restaurer

cd iam-invoicer/deploy
docker compose stop app
docker compose exec -T db pg_restore -U iam -d iam_invoicer --clean --if-exists \
    /backups/iam-invoicer-AAAAMMJJ-HHMM.dump
docker compose start app

Serveur du bureau

# Sauvegarde
pg_dump -h 192.168.1.10 -U iam -d iam_invoicer -Fc -f iam-invoicer-AAAAMMJJ.dump
# Restauration (applications fermées sur tous les postes)
pg_restore -h 192.168.1.10 -U iam -d iam_invoicer --clean --if-exists iam-invoicer-AAAAMMJJ.dump

Sous Windows, planifiez pg_dump avec le Planificateur de tâches, et copiez les fichiers sur un disque externe ou dans un stockage en ligne.

À sauvegarder aussi

Le fichier deploy/.env (mot de passe de la base) et, pour Android, la clé de signature .jks. Sans eux, il est impossible de remonter le serveur ou de mettre à jour l'application sur le Play Store.

14 Mises à jour

  1. Sauvegardez d'abord (chapitre 13).
  2. Serveur en ligne : 
    cd iam-invoicer
git pull
docker compose -f deploy/docker-compose.yml --env-file deploy/.env up -d --build
    La base est mise à niveau automatiquement au démarrage (migrations). La version navigateur est à jour dès le rechargement de la page.
  3. Windows : lancez le nouvel installateur par-dessus l'ancien. Les données et l'identifiant d'application sont conservés, y compris depuis l'ancien « IAM ERP ».
  4. macOS : remplacez l'application dans Applications.
  5. Android et iOS : par le magasin, TestFlight ou un nouvel APK. Synchronisez les opérations hors ligne avant de désinstaller une version.
Ordre de mise à jour

Mettez à jour le serveur en premier, puis les postes. Avec un serveur du bureau, mettez à jour tous les postes en même temps : le premier poste mis à jour fait évoluer la base, ce qui peut gêner les postes restés sur l'ancienne version. Ne revenez jamais à une version antérieure sur une base déjà mise à niveau.

16 Fabriquer les applications

Avec GitHub Actions (recommandé, sans Mac ni Android Studio)

Sur une étiquette de version, tous les installateurs sont publiés dans une Release GitHub, avec le fichier d'empreintes SHA256SUMS.txt.

  • Déclenchement : en poussant une étiquette de version (git tag v0.5.1 && git push --tags), ou depuis Actions → build → Run workflow.
